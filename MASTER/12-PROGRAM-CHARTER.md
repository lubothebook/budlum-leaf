## 1 · The charter, in plain words

1. **The program never closes**. A phase ends; the program does not. Every block of work produces a deliverable, a record and a next block.
2. **The program lead is the AI**. It plans, sequences, writes, checks and reports. Ayaz decides the identity of the product and approves a decision; it does not carry the program.
3. **Every turn of the program leaves the workspace further ahead than it found it**. A turn without a new artefact, gate result or decision is logged as defective.
4. **A deliverable is a file, a number and a gate**. A file alone is a draft. A number without a gate is an opinion. A gate without raw data is a wish.
5. **The three lines run at once** (Ayaz, question 24): the **drawing**, **software** and **partner** lines. Each line has a weekly output.

## 5 · What the program does with a question from Ayaz

1. It records the question with a number.
2. It answers with a recommendation and the number that supports it.
3. It writes the answer into the volume that owns the subject, and into a revision log.
4. It changes every dependent number in every other volume, and it re-runs the consistency checks.
5. It states the new open items, and it asks the next set of questions.

**This is the loop of the program, and it is the answer to "program yourself for continuous work"**. `[DECISION]`

## 6 · The consistency checks of the program

| The check | What it finds | How often |
|---|---|---|
| the number checks | a quantity that two volumes state differently | every revision |
| the tag checks | a number without a tag, a claim without a gate | every revision |
| the name checks | a device class word in a claim, a file name or an identifier | every revision |
| the drawing checks | an overlap, an overflow, a covered text, a stale footer | every drawing change |
| the plan checks | a block with no owner, a gate with no data | every week |
| the claim checks | a sentence that the gates do not support | every public text |
